# The Nano Brief: YOU BE THE COMPUTER 

the idea in this assignment is to turn a fellow student into a *Human Drawing Machine* (`HDM`). in order to do so you will need to write down a series of commands which we will call from here on *Machine Control Program* (`MCP`).

to make this work a few rules must be honored:

- do not communicate with the `HDM` in human language or gestures or any other biological-brain based mode of communication. the `MCP` is the only way.
- only use very simple and abstract drawing commands like `draw a line` or `make a dot`. try avoiding complex commands like `draw a city`.
- all drawings must be executed on a white DIN A4 sheet of paper in portrait format, with a single color drawing pen.
- do not use additional tools except for rulers.
- try not to exceed 30 lines of commands.
- you may refine your program if it did not produce satisfying results on the first run. your `HDM` may execute it again … and again … and again …

a few hints and suggestions:

- make use of iterations, conditions, references, and calculations ( e.g `draw a first line + draw a second line that intersects the first line + draw a circle at the intersection with half the size of the first line`.
- develop your own notation or vocabulary.
- from an aesthetic point of view an `MCP` is usually better if it generates interesting output from simple commands used in a novel or unexpected fashion.

when satisfied ( or when time is up ) choose your favorite `HDM DRAWING` and print out the associated `MCP` on another DIN A4 sheet of paper in portrait format with 20mm border, as a font use `JetBrains Mono, 12/14.4pt`. this produces the `MCP PRINT_OUT`. to complete the assignment stick both on the designated wall with `HDM DRAWING` on the left and `MCP PRINT_OUT` on the right. see illustration below:

```
   +-----------+   +-----------+
   |           |   |           |
   | HDM       |   | MCP       |
   | DRAWING   | + | PRINT_OUT |
   |           |   |           |
   |           |   |           |
   +-----------+   +-----------+
```

## ON REFLECTION

this assignment already is a program. a program that turns you into a machine to execute our intentions. a program to create programs. you might want to contemplate three aspects on your way home tonight:

a/ what can be described in programs? find aspects of your banal everyday life you can describe as sets of instructions ( to yourself mostly ). and try to create, and run or simulate, some examples in your head ( for example taking a shower or brushing your teeth ).  
b/ programming languages must be free of ambiguity … human language is definitely not free of it. how much ambiguity did the assignment contain? where did you take advantage of it? would it even have been possible for us to give you an assignment free of ambiguity? so what are the limits of programming languages, of human language, and where do they overlap? ( see for example: [Ishac Bertran: Code Poems](http://code-poems.com) )  
c/ what is the relation between programs and freedom? it is a common belief that rules constrain freedom but is this always true? how much did the instructions in this assignment constrain your ideas and how much guidance did the instructions supply you with to foster your own creativity in the first place.
